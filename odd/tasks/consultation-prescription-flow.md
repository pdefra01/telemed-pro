# Feature: Consultation prescription flow (diagnosis / receta / prescripcion + WhatsApp)

## Objective
Simplify how the doctor closes a consultation. Three separate things, all
reachable during the video call and finalized in PostConsultation:
- **Diagnostico**: unchanged (already required).
- **Receta**: the medications, printed in a plain PDF. Catalog picker (stock
  deduction kept) plus free-text lines that live together in the same
  `medications` array. NO digital signature anywhere (flow or PDF).
- **Prescripcion**: free-text non-medication indications (rest, diet, studies).
- Receta (PDF) and prescripcion (text) are both delivered to the affiliate by
  WhatsApp from the company number (WAHA, already linked and WORKING).
- **Obra social alternative**: for affiliates who need an insurer-issued
  prescription, the doctor generates it in an external phone app and pastes the
  download link; the system sends that link to the affiliate through the
  company WhatsApp instead of generating the internal PDF.

## Decisions (user-confirmed 2026-09-23)
- Free text COEXISTS with the catalog (catalog stays for stock deduction).
- Receta = medications in a PDF; "nothing signed or weird" -> remove the digital
  signature from the flow AND from the PDF.
- Prescripcion = non-medication indications, free text.
- Reconnect the existing but disconnected "Receta" tab in `VideoRoom.tsx`
  (`RxItem { med, dose }`, `recommendations`) instead of building new UI; its
  content must reach PostConsultation (navigate state) and be prefilled there.
- Obra social is an ALTERNATIVE mode at prescribing time (not both): doctor
  pastes the external app's download link; sent via company WhatsApp.

## Findings (mapping, 2026-09-23)
- `VideoRoom.tsx` ~L522-600: "Receta" tab exists (state at ~L876) but
  `handleCompleteAppointment` (~L1004-1016) only saves notes and navigates to
  `/doctor/post-consultation/:id`; prescription/recommendations are dropped.
- `PostConsultation.tsx`: `MedicationItem {name, instructions, productId?,

  (`appointmentId, diagnosis, notes, medications, digitalSignature,
  signaturePublicKey`); stock deducted client-side after invoke when
  `productId` exists; WhatsApp send fires only if `data.pdfUrl` is returned.
- `supabase/functions/finalize-consultation/index.ts`: builds the PDF with

  `notes` TEXT autogenerated "Recetado para: ...", `digital_signature TEXT NOT
  NULL` with an `AUTH-...` fallback).
- `server/whatsapp.js` `sendPrescriptionViaWhatsApp` sends the PDF via
  `sendFile`; `prescription_deliveries` needs a `prescription_id`.
- Root cause of the "receta not delivered" test on 2026-09-23: no `pdfUrl` was
  produced, so the WhatsApp endpoint was never called (`prescription_deliveries`
  was empty). The gateway itself was verified working (sendText + sendFile OK).

## Design (assistant)
- No DB migration by default (production DB, user asked for care):
  - Prescripcion is stored in the existing `prescriptions.notes` TEXT (replaces
    the autogenerated "Recetado para").
  - With the signature removed, `digital_signature` stays NOT NULL and the
    server stores an empty string (honest "no signature", satisfies the
    constraint).
- Receta PDF prints only medications (name + instructions) with no signature
  block. Prescripcion travels as a second WhatsApp text message after the PDF.
- Obra social mode: doctor selects mode, pastes an https link (validated), no
  PDF is generated; server sends a WhatsApp text with the link. Delivery log:
  `prescription_deliveries` requires a prescription id, so T5 must decide
  between creating a minimal `prescriptions` row (no PDF) or a written-only
  migration. Any migration is WRITTEN ONLY and applied only after explicit
  user confirmation.
- The edge function change requires a deploy to take effect in production:
  a separate user-authorized step, not part of the code tasks.
